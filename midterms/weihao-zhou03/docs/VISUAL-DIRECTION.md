# 回声渔场 · 视觉与交互方向

状态：首版实施提案，2026-10-22。依据 `src/core/types.ts` 与 `docs/INTERFACE.md` v1 编写；没有把提案视为已通过审美或趣味性验收。下列尺寸、节奏、色值均是原型起点，后续应根据实际运行截图和真实试玩修订。

## 1. 画面应先讲清楚什么

海湾是画面的主角：一艘亮着暖灯的小船停在深靛蓝水面，礁石形成清晰的航道，声波在水面留下短暂的青绿几何痕迹。玩家看见的是被声音暂时照亮的信息，海面并不因为界面漂亮而暴露鱼和巡声者。

整体采用“夜航海图 + 微缩低模场景”的一致语言。大面积留白、简洁字级、细分隔线和少量实底操作区提供克制的编辑式 HUD。不堆叠玻璃质感卡片，不依赖霓虹描边、厚重阴影或一直闪烁的红灯制造紧张。

三个第一眼识别目标：我的船在哪里；我目前知道什么、线索有多旧；这次行动会花掉什么、是否面对已经预告的攻击。

## 2. 色彩与材质

| 用途 | 提案色值 | 约束 |
|---|---|---|
| 页面及深水底色 | `#07151F` | 接近墨蓝，保持深色层次 |
| 海面主体 | `#0A2533` | 与陆地、船体分离 |
| 浅水/海湾层次 | `#123C49` | 以低对比大面变化表达地形，不暗示隐藏生物 |
| 礁石暗部/亮部 | `#203B45` / `#547078` | 岩体轮廓要可读，避开青绿线索色 |
| 正文/次级文字 | `#E8EEE9` / `#A0B6BA` | 不把小字压到难以读取的灰度 |
| 弱分隔线 | `#34515C` | 1 px，必要时随底色调整 |
| 声学信息 | `#6CDDD1` | 主动脉冲、近期回波、活跃声标 |
| 旧信息 | `#829EA4` | 依靠虚线、年龄和扩大的范围区分，不只靠减淡 |
| 船灯/港口/已交付价值 | `#F0BD70` | 暖色只集中在船、港和有限关键数字 |
| 风险/高张力 | `#F47767` | 攻击通道与明确危险；不要用作所有按钮底色 |

海面可以有宽缓的波纹、轻雾和有限反光。装饰浪花是低对比短弧，声波是围绕公开事件位置的连续同心线，两者在形状与动势上都区分。避免高频噪点遮盖回波和细鱼线。

船采用奶白舷侧、靛蓝船底、木色甲板、一盏琥珀灯；三个大形体比大量细件更重要。礁石采用少量粗糙平面与明确明暗面，不拼接不同来源的写实素材。所有构造首先用程序几何完成，新增外部素材必须补许可。

## 3. 字体与排版

不请求远程字体。中文正文使用 `"Microsoft YaHei UI", "PingFang SC", "Noto Sans CJK SC", system-ui, sans-serif`；品牌英文可用 `Georgia, "Times New Roman", serif`；数字使用 `"Cascadia Mono", Consolas, monospace`。

| 层级 | 原型起点 | 用途 |
|---|---|---|
| 入口中文标题 | 44–56 px，常规字重 | 回声渔场 |
| 游戏中文标题/结算标题 | 24–32 px | 不与海域争夺主导位置 |
| 任务名称/面板标题 | 18–22 px | 单一短句 |
| 正文/主要操作 | 14–16 px，行高 1.5 | 中文不依赖超细字重 |
| 元信息 | 12–13 px | 回波年龄、模式、快捷键 |
| 品牌眉题 | 11 px，英文间距约 0.18em | ECHO FISHERY，小范围使用 |

英文品牌只在入口、页眉与结算出现。主操作、状态、说明优先中文。次要文字不低于 12 px；禁止把玩家必须理解的规则藏进 10 px 的角落。

## 4. 场景与投影

固定正交相机，高角度斜俯视，第一版不提供旋转和缩放。世界使用二维连续坐标；所有船位、港口、礁石、声标、鱼线、回波中心、攻击走廊均通过同一坐标映射投影。

海面约占游戏区 70–80%；船在默认截图中仍有清晰的船首方向和暖灯。海湾全貌可见，必要时以窄边框与航海刻度收束构图；不要为了装饰裁掉边缘合法航行区。视角让礁石提供体积，但不能把海域压成只剩一条窄带。

船的浮动、灯光、尾流与海浪只改变视觉。尾流只反映已公开的船行为。未发现的鱼和巡声者不产生可定位的模型、阴影、灯光、涟漪或尾流。船被岛礁挡住时应出现船体轮廓或公开位置标记。

声呐世界圆自然投影成椭圆，不另画屏幕空间圆来冒充范围。移动/切线预览检查同一条世界轨迹，障碍区域不因绘制阴影而变大。朝向为 N 时世界 y 减少；界面必须有明确北向标记，方向盘和投竿方位不得随镜头含糊变化。

## 5. 桌面主布局

1440×900 是首次检查的参考尺寸，另检查 1280×720 与窄窗口。外侧安全边距约 24–32 px，使用 8 px 间距倍数。

| 区域 | 尺寸提案 | 内容 |
|---|---|---|
| 顶部页眉 | 高约 76 px | 左为眉题和中文名；中为任务短句；右为静音/帮助/重开 |
| 海域 | 中部尽量完整，约 65–75% 高度 | 船、港口、礁石与公开线索；不要有不透明大卡片盖中央 |
| 左上边注 | 宽约 210 px | 任务配额、剩余行动、当前阶段；位于海域安全边界 |
| 右上边注 | 宽约 190 px | 船体格数、声标库存、船上渔获；不用重复大仪表 |
| 底部操作带 | 高约 150–190 px | 当前模式、方向选择、主要动作与成本说明 |
| 事件短记 | 海域左下，最多 3 条 | 最新事件在上，旧条目可展开；不持续刷屏 |

页眉与操作带可用不透明深蓝底。海域边注用文字、短线和极轻背景保障可读，避免四面都挤满按钮。剩余行动不称作现实分钟；等待玩家思考不会扣步。

方向选择与动作选择必须是显式的。八方向罗盘/键盘快捷键可辅助操作，鼠标点海域只负责选择公开方向并预览；不悄悄提供比 Agent 更精确的连续移动动作。当前选中方向、拟执行动作、一步成本在按钮按下前可见。

在 1280×720 下缩小非必要页眉留白，操作带转紧凑两行，不能用缩到 10 px 的方式硬塞。低于约 960 px 宽时将边注移到顶部信息行，操作区允许内部自然换行，不把主海域压成方寸。移动端只是适配目标，未验证前不要声称已经完整支持。

## 6. 声学信息的视觉语法

| 信息 | 表现 | 必须避免 |
|---|---|---|
| 新弱/强声呐 | 船位发出的 1–2 圈青绿细线；强弱有文字/线型区别 | 凭动画渲染范围擅自增加探测规则 |
| 鱼群回波 | 空心细圆/短弧标记，旁注鱼群类别与“观测于第 n 步” | 显示真正鱼模型或稳定追踪身份 |
| 大型异常 | 不同形状的宽弧与“异常”文字 | 只有换颜色，或暗示精确危险状态 |
| 旧回波 | 固定中心、虚线不确定范围、`距今 n 步` | 根据真实鱼位挪动中心；按墙钟时间消退 |
| 待启动声标 | 灰青轮廓、清晰数字 `2步后` | 用快速倒计时造成现实时间压力 |
| 活跃声标 | 实心小浮标、规律声圈、声型文字与剩余步数 | 把装饰声圈边缘当成未公开的吸引半径 |
| 方向性危险 | 海域边缘的短弧/小箭头和“东北·接近” | 从 bearing 推导并显示隐藏坐标 |
| 已预告攻击 | 真实公开走廊，珊瑚边界、低密度斜纹和箭头 | 只在船上闪一个红点而不显示可逃区域 |

回波变旧是游戏步变化：新观察到达时才更新年龄和不确定范围。动画播放完后线索仍应按规则保持，暂停等待不能让它视觉消失。`contacts` 使用观测局部 ID，不在 UI 创造跨探测的稳定鱼群标签。

关键风险始终有文字与形状。攻击提示优先写“冲撞通道已形成 · 下次行动后结算”，仅在 `resolvesIn` 与公开契约匹配时使用；若时序变化直接读取公开值，不能把固定文案做成错误承诺。

## 7. 探索与搏鱼操作

探索操作组分为航行、主动探测、声标、下竿；当前选择组明确高亮，其余组保持低视觉权重。安静/急行、弱/强脉冲、轻响/低鸣与立即/延迟启动均采用可见文本，不能仅靠图标猜。

按钮文案应提示取舍，如“安静航行 · 较近/低噪”“急行 · 较远/高噪”。数值距离或强度只有在公开规则定义并同步提供给模型时才显示。禁用按钮说明公开原因，不能因附近没有隐藏鱼而禁用下竿。

搏鱼时底部整块切换成紧凑作业台：

- 左：鱼种、当前行为提示，以完整短句写“下一次收线面对：疲惫/拉扯/冲刺”。
- 中：捕获进度与张力，各有条形和准确数字；数字与 `PublicObservation.fishing` 一致，禁止模型只见分档、人类看精确值。
- 右：稳收、强收、放线三按钮；“切线急避”单独排列，必须先选方向并显示轨迹。

强收不是永远红色或标成“错误”；高张力时提供状态提示，但不替玩家做策略决定。切线急避为显式单次提交，按钮写清“放弃本条鱼并向东北急避”；不弹二次确认消耗真实反应节奏，也不先切鱼再要求下一步移动。

危险走廊出现时不能用新大弹窗盖住地图；提升边界与文案对比，保留全部应对动作。非法动作显示短且具体原因，游戏 tick 不变化，界面不能先演出成功动作。

## 8. 入口、教学与结算

入口保持同一海湾场景作背景，左侧约 40% 放品牌、两行定位与“选择本次出航”列表；右侧保留可辨认的小船和礁石。任务 A/B/C 采用三条清楚的纵向条目，显示任务名、目标与行动预算，不制作三张营销大卡片。教学入口和静音开关始终可见；不展示未开始场景的鱼或危险布局。

教学采用逐步边注，允许跳过与重新查看：

1. 一次指令推进一步，等待输入不扣时间；北向与港口可见。
2. 弱脉冲提供当时线索；回波会旧，不跟踪鱼。
3. 声标在当前位置留下声音，可延迟启动；声音会同时影响鱼和危险。
4. 当前鱼行为影响下一次收线；强收用噪声和张力换时间。
5. 冲撞通道先出现再结算；切线急避是放弃当前鱼换移动。
6. 船上渔获只有主动回港结算才交付；达到配额不等于已安全完成。

说明“礁石挡船、不隔音”，不能让美术暗示声学遮挡。教学只是讲解公开规则，不主动显示隐藏目标。新术语第一次出现才解释，后续不重复覆盖界面。

结算使用窄实底层与可见海湾背景，标题明确区分“任务完成”“提前返航”“船只沉没”“夜晚结束”“运行器终止”。展示交付渔获、目标进度、船体、行动数；在海上的捕获和最终交付分列。提供“同任务再试”“选择任务”，不要把失败包装成成功庆祝。

结束前不提供上帝视图。终局后如增加全路线复盘，必须明确标“终局复盘 · 含隐藏信息”，且与实时玩法/模型输入隔离；首版没有完整私有复盘数据时不伪造轨迹。

## 9. 声音与可访问性

首次用户手势后开启音频，默认音量克制，顶栏提供静音。声呐为短促清亮音，声标有可分辨节奏，强收与挣扎增加粗糙感，攻击预警单独占用明显短音；不叠加长时间高响度告警。

所有决策相关声音来自公开事件；同一事件在文字和画面都有对应。立体声的方位精度不得超过模型接收的信息，`bearing` 只有八方向时不要用隐藏位置精确声像定位。装饰环境音不能传递未公开实体位置。

静音可玩。减少动态效果设置可关闭镜头震动和扩散动画，保留静态公开边界与文字。风险、旧回波、声标声型不只用色相区别；键盘焦点清晰；互动目标参考 40–44 px 的点击高度。

## 10. 首次视觉验收清单

这些是待执行检查，当前没有截图或人工试玩证据。

- 1440×900 和 1280×720 下，船、港口、北向与主操作第一眼可找；不存在面板盖住合法逃逸方向的问题。
- 一张不带解释的截图能区分装饰波纹、当前声波、旧回波与冲撞通道。
- 坐标映射一致：贴礁移动、投竿、声呐边界、切线轨迹与实际结果对应。
- 回波至少经历新鲜、变旧、到期三个游戏步状态；等待一分钟不让规则信息消失。
- 切换探索/搏鱼/终局无布局跳动、按钮截断或信息重叠；高张力与攻击同时出现时仍看得清应对方向。
- 开音与静音都能理解风险；没有未发现鱼影或危险尾流泄漏。
- 实际事件、失败、玩家反馈如实记录；截图好看不代表声音核心已被验证。

设计 Agent 交接只覆盖视觉/交互提案，不审批规则、课程 gate 或模型实验。任何需要新增公开字段、动作或数值含义的设计，先交核心负责人更新契约与规则测试，再实施界面。
